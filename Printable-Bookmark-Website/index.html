Printable Bookmark Generator

Printable-Bookmark is a Python script, main.py, that reads one Pinterest board of printable bookmarks and saves every pin page it finds into the folder you run it from.

01 / What this job is

My README for this repo is three lines long, so this page takes its facts from main.py itself. The script was written for one board, the printable bookmarks board named in the BOARD_URL constant at the top of the file. I put that URL in one place on purpose: it is the only thing a user of this script is expected to change, and retargeting the script should not mean hunting through functions.

Run it and the script fetches the board page, finds every pin link on it, follows each one, and writes each pin page to disk under a file name taken from the pin URL. It prints one line per saved bookmark and a count at the end. That is the whole job. It does not print anything itself, crop anything, or lay out a sheet. The name describes the board it serves, not a printer driver, and I would rather be clear about that here.

What the script is careful about is the fetching. Boards change, links arrive in odd shapes, and connections stall. Most of the code, and most of the spec sheet below, is about those three facts.

02 / Spec sheet, from the code

Source boardBOARD_URL at the top of main.py, one Pinterest board of printable bookmarks. Change this one constant to point the script at a different board.
Pin markerPIN_LINK_CLASS = "GrowthUnauthPinImage". The script finds pin links by this CSS class. Pinterest renames its classes without notice, so I treat this as a maintenance point, not a constant I can trust forever.
Fetch timeout15 seconds, set per request in the fetch helper. Not per run: a board with many pins can take longer than 15 seconds in total. Without a timeout, a stalled connection hangs forever with no message, which reads exactly like the script working.
Relative linksPin hrefs come back as relative paths like /pin/123/. The script resolves them against https://www.pinterest.com before downloading, instead of handing requests a path it cannot use on its own.
File namesfilename_for parses the URL with urlparse and takes the last path segment, query string ignored. A hand split returned the domain as the file name for a root URL. The parsed version falls back to the name "bookmark" when the path is empty. No extension is added: the bytes are saved exactly as they arrived.
ParserBeautifulSoup with the built in html.parser. It comes with Python, so the install list stays at the two packages named in the file header.
Error copyA network failure and an HTTP error get separate messages in fetch, because they point at different fixes. A failed pin does not stop the pins after it.
Zero resultIf nothing downloads, the script prints that the board is either empty or the markup no longer matches PIN_LINK_CLASS, and exits with code 1. The old behavior printed nothing at all, which is indistinguishable from success.

03 / How a run goes

  1. Fetch the board. One GET through the fetch helper, timeout and status check included.
  2. Find the pins. Every link carrying the pin class is collected. Links with no href are skipped.
  3. Resolve and download. Relative hrefs are made absolute against pinterest.com, each page is fetched on its own, and the bytes are written in binary mode with no decoding step in between.
  4. Report. One "Downloaded bookmark" line per file, then a final count. Zero files means the warning above and exit code 1.
# needs the two packages named in the header of main.py
pip install requests beautifulsoup4

# then, from the folder you want the pages saved into
python3 main.py

04 / Known fault on this ticket

Margin note, mine: if two pins end in the same last URL segment, the second write overwrites the first with no warning, and the saved count still goes up for both. I have not hit it on this board, where pin ids differ, but the comment sits in the code so it is not a surprise if a file ever seems to be missing.
